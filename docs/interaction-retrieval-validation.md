# 对话检索、资料阅读和整理删除验收

日期：2026-10-24。保留现有字体、主题及已保存模型连接，不改版本号。

## 实现与边界

- 来源默认单行展开并在末端渐隐，保留真实来源按钮；可展开完整列表。正常算法/评分说明从聊天和搜索界面移除，配置、索引或网络降级提示仍保留。
- 问答范围使用知识库、文件夹、标签三个分页签；保存的会话仍不可扩大范围。输入区显示实际知识库、目录和标签名称。
- 左右栏增加过渡并尊重减少动态效果；右栏收起后保留资料管理、最近文档等快捷入口，以及已打开文档/页码/引用状态。迟到的来源请求不能重新展开已收起侧栏或覆盖新文档，关闭后焦点返回可见操作。
- 阅读器拆出 `DocumentReading` / `PdfNavigation`；PDF原件与当前页文字分开，引用片段默认两行，可展开及定位。支持适应宽度、缩放与翻页；渲染任务串行取消，防止同一canvas并发渲染。收起后暂停阅读器轮询和渲染。
- 整理记录与方案详情各自滚动。整理可提议删除空目录和标签，预览及额外确认展示受影响文档。删除不移除原文件；完整撤销恢复目录、标签原ID/颜色/别名与文档关联。资源变化、关联变化、恢复重名均拒绝危险覆盖。
- 主动检索为单条消息开关，默认关闭，不增加普通聊天的规划调用。支持工具的连接使用只读 `search_knowledge(query)`；否则使用明确标识的JSON检索规划。最多两轮、三次实际搜索尝试，失败也计预算。原会话范围始终由服务器固定，网络等待后重验权限与过滤。未暴露模型隐藏推理。

## 真实模型与真实API

使用单独创建、明确标注为一次性验收的知识库；只上传154字节合成Markdown。当前保存连接未开启原生工具能力，因此真实验证的是JSON规划路径，原生工具路径由受控网关测试验证，没有偷偷修改能力声明。

问题为“冷桥项目由谁负责归档？每周什么时候备份？”。模型实际生成“冷桥项目 归档 负责人”和“冷桥项目 每周 备份 时间”两条搜索词，第二轮判断已有足够证据后停止：rounds=2，searches=2，fallback=false。约12.2秒完成，正确回答林舟、每周五15点，引用唯一合成文档的真实chunk。各阶段与搜索词写入消息execution并可刷新恢复。这只是轻量功能验收，不代表大规模召回或延迟基准。

另在同一合成库创建一个空目录和一个关联该文档的标签，通过受控计划验证审批执行器（计划明确标注非模型生成）：

1. 未传额外确认返回409，文档版本不变。
2. 显式确认后空目录进入回收站，标签及关联移除，文档内容保留。
3. 撤销成功，恢复3个实体/关联快照；原标签ID、颜色、别名与空目录均恢复。

浏览器已检查受影响文档清单和最终确认弹窗；实际执行及撤销通过隔离fixture的HTTP API完成。未替用户批准、拒绝或撤销日常知识库中的方案。
