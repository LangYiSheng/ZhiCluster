## 开场与追问准备

开场可以说：“这两周我参考 ima 的个人知识库使用思路，做了一个叫知簇的 Web Demo。目前已经打通资料导入、范围检索、知识问答和引用溯源。接下来用一组实际资料说明功能，再介绍实现方式。”

| 可能的问题 | 回答要点 |
| --- | --- |
| 是不是只调用了大模型接口？ | 模型负责生成语言；我实现了文档解析、结构切块、索引、范围过滤、检索融合、后台任务，以及回答与原文的引用关联 |
| 是自己训练的模型吗？ | 当前没有训练模型，调用现有聊天与 Embedding 服务，重点是知识库应用流程 |
| 为什么需要向量检索？ | 关键词适合精确术语，向量检索补充语义相近的表达；两路融合后再选择证据 |
| 引用是不是模型编出来的？ | 候选引用关联数据库里的真实文本片段和来源锚点，完成时保留实际使用的允许来源；但有引用仍需核对结论是否被原文支持 |
| 和 ima 的关系是什么？ | 参考个人资料管理与基于资料问答的使用思路，当前展示自己的 Demo 和实现范围，不声称复现完整产品 |
| 能否多人在线使用？ | 当前是免登录单用户版本；公开多人使用需补认证、用户隔离及相应并发验证 |

## 2 核 2G 是否适合演示

**结论：可以作为轻量单人演示的部署目标，尚未在实际 2G 主机上验证。** 前提是聊天与 Embedding 均调用外部服务，不在这台机器上加载模型权重，提前完成少量样例资料入库，并避免同时解析多个大文件。

本轮读取日常项目容器的一次轻负载快照如下，仅统计 `zhicluster` 项目，没有把其他隔离验收服务算进去。

| 服务 | Docker 报告的内存使用 |
| --- | ---: |
| Nginx 前端 | 24.64 MiB |
| FastAPI API | 247.10 MiB |
| Python worker | 66.57 MiB |
| PostgreSQL | 65.47 MiB |
| 合计 | 403.78 MiB，约 404 MiB |

该数值没有包括宿主操作系统、Docker 守护进程和其他服务，也不是文档解析或问答期间的峰值。`/api/ready` 当前返回 ready；模型状态显示聊天及向量连接已配置，这只确认配置状态，不替代重新验证外部服务可用性。

对于已有的 2 核 2G Linux 服务器，可以先试运行；如能自由选择配置，4G 会更有余量。CPU 主要影响解析和检索，模型调用还取决于网络及外部服务响应。内存是否够用最终应以目标机器完整跑一次“上传、索引、提问、引用打开”并观察峰值为准。

部署时建议：

- 使用标准运行配置，不运行 Vite 开发服务，不同时启动 eval、redesign-check 等隔离验收栈。
- 将 `WORKER_INGESTION_CONCURRENCY` 从默认 3 调为 1，放入服务器 `.env`，重建 worker 容器后生效；提前入库 3–10 份小样例，演示时以问答和阅读为主。
- 小服务器尽量运行预先构建好的同架构镜像。构建与运行是不同负载，不能由约 404 MiB 的运行快照推断构建也能稳定完成。
- 磁盘可按 20 GB 级别预留，并检查实际可用空间。当前后端单个镜像显示约 1.36 GB，包含旧 Office 转换依赖；镜像大小属于磁盘占用，不等于需要同等大小的内存。多个镜像存在共享层，不能直接把显示大小相加当作真实磁盘需求。
- 可用 1–2 GB swap 作为内存突增的缓冲，但它会变慢，不能代替足够的物理内存。Docker 的说明见[资源限制](https://docs.docker.com/engine/containers/resource_constraints/)。

## 临时远程演示的访问方式

当前 Compose 将网页、API 和数据库端口绑定在 `127.0.0.1`。后端还检查 Host、Origin 和运行环境，所以不能仅把网页端口暴露到公网就认为完成部署。

如果现场电脑可以使用 SSH，可保留服务器本地访问限制，通过 SSH 隧道临时查看。服务启动在服务器上，在现场电脑执行以下示意命令，将用户名与主机名替换为真实值：

```text
ssh -N -L 3000:127.0.0.1:3000 your-user@your-server
```

随后在现场电脑浏览器打开 `http://localhost:3000`，并保持 SSH 连接。这个端口与项目默认允许的来源一致；如果现场电脑已占用 3000，需要提前处理。此方式依赖现场 SSH 客户端、登录条件及网络，必须提前在另一台电脑验证；不需要将 SSH 凭据写进飞书文档。

若希望老师仅用一个公网链接直接打开，需要单独设计带认证的 HTTPS 入口，并适配当前 Host、Origin 限制。API 和数据库仍应保持私有。Docker 的[端口发布说明](https://docs.docker.com/engine/network/port-publishing/)解释了绑定 localhost 与公开发布的区别。

新服务器可重新导入少量公开样例并单独配置模型。若要完整迁移本机状态，需要数据库、上传原件、runtime 主密钥配套迁移；仅复制代码不会包含已有资料。暂未提供服务器地址或访问条件，本轮没有执行服务器部署。
