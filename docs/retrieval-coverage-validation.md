# 长正文与短尾片段的方向性判重实验

日期：2026-10-24。本文记录可信快照上的独立候选实验；截至本次记录，产品 `ranking.py` 没有应用此改动。只读使用隔离 PostgreSQL 25432 中的 CMRC2018 专用知识库，不调用模型，不修改用户资料或保存配置。

## 真实问题与最小候选

原多样性排序把同文档片段的指纹重叠率定义为 `交集 / 两者较小的指纹集合`。如果已选中一个短尾段，而待选长正文完整包含该尾段，就可能把长正文视为重复，即使正文的大部分证据尚未展示。

先行失败复盘中，索莫尼发行机构的问题已找到正确文档，但含答案的长正文被短尾片段触发重复折扣；索齿兽目的别称也有同类问题。全部原始答案都在真实 chunk 中，没有通过修改答案、切片或查询来掩盖问题。

独立快照只将判重分母改为**待入选候选**的指纹集合大小：

```text
A = 已选片段的归一化 5 字符指纹集合
B = 待入选片段的指纹集合
原规则：|A ∩ B| / min(|A|, |B|) > 0.65
候选规则：|A ∩ B| / |B| > 0.65
```

阈值 0.65、重复折扣 0.35、文档计数折扣、600 候选窗口与权限复核全部保持原值。评估查询使用数据集的原问题；答案仅用于判定结果是否包含真实证据，没有用答案或标题引导检索词，也没有按失败样本挑选新阈值。

这个方向保留两条边界：展示长正文后，已被覆盖的重复短尾仍降权；真正接近重复的长段落仍降权。只修正“短尾已经展示，长正文仍包含大量新信息”的反向误判。

## 先行失败样本与全量中文复测

先对原 32 条答案@5缺失样本重放。基线逐题精确匹配冻结的 600 API 记录；候选恢复 2 条、没有倒退，其余 30 条不变。没有以这组已知失败作为最终门禁，随后完成全部 3219 条问题的旧/新配对。

完整配对中，每题都重新执行基线并核对原 API 的来源列表、预期来源排名和各项指标一致，然后比较候选。实际返回来源和答案按原始文档 ID、真实片段正文评价；整个过程为只读事务，有固定源码哈希和每 5 题的身份校验断点。

| 指标 | 基线快照 | 方向性候选 | 逐题变化 |
| --- | ---: | ---: | --- |
| 来源 Recall@1 | 0.963964 | 0.963964 | 3219 条均不变 |
| 来源 Recall@5 | 0.994719 | 0.994719 | 3219 条均不变 |
| 来源 Recall@10 | 0.996893 | 0.996893 | 3219 条均不变 |
| 来源 MRR@10 | 0.977501516 | 0.977501516 | 3219 条均不变 |
| 前 5 片段含正确来源和答案 | 3187 / 3219 | 3189 / 3219 | 2 条改善、0 条倒退、3217 条不变 |

改善的问题为：

- `DEV_514_QUERY_1`：索莫尼由什么机构发行？
- `DEV_1669_QUERY_0`：索齿兽目又叫什么？

全部 3219 条的前 10 文档序列和集合也完全不变；仅 8 条问题的前 5 片段序列变化。来源文档排对与回答所需片段可用是不同指标，本次收益是证据片段覆盖，不能包装成来源 MRR 提升。

答案@5从 99.005902% 到 99.068034%，原有缺失从 32 条减少为 30 条。这是具体的小幅修复，剩余失败未解决，也未调用真实生成模型来宣称答案已经生成正确。

## 两份英文完整 test 的交叉门禁

SciFact 300 条、NFCorpus 323 条全部按原始语料与 qrels 运行基线和候选，两份结果的每题前 10 排名及每题 Recall/MRR/nDCG 逐项相同：

| 数据集 | Recall@10 | MRR@10 | nDCG@10 | 改善 / 倒退 |
| --- | ---: | ---: | ---: | --- |
| SciFact | 0.766167 | 0.601214 | 0.636455 | 0 / 0 |
| NFCorpus | 0.137769 | 0.477603 | 0.287117 | 0 / 0 |

这些 BEIR 运行每文档仅一个摘要片段，因此不能单凭英文指标不变就证明长短片段行为正确。额外的小回归明确验证：选短再选长时保留长正文，选长再选短时压低重复短尾，真正近重复仍降权。源码有效差异复核确认仅一处判重分母变化，未混入其它参数调整。
