# 检索、入库与交互优化验收

日期：2026-10-23。使用现有 PostgreSQL、原始附件及用户保存的模型配置。真实调用仅用于少量检索、短问答、两篇合成短文及一次有界证据筛选；未更改凭据、未重建用户全部索引。

## 实现边界

- worker 默认 3 个入库槽和独立的 1 个交互槽；任务有空槽才领取，各自持有配置快照、Session、租约和心跳。同文档领取在文档锁后再次检查活动租约。
- 同进程网关共享模型并发上限，默认 3 槽中的 1 槽可供交互使用。多进程之间不宣称全局限流。短写事务统一 namespace/job/document 锁序，模型网络等待不持有这些写锁。
- 小文档一次生成全文摘要，长文有界并行并由协调线程保存检查点；摘要不要求凑字数。DOCX 合并单元格按底层 XML 单元格去重。
- 检索拆分查询规划、词面打分、融合、多样性、文档用途先验和可选模型筛选。明确找表、填表及统计数据表不因通用表单先验被降权。网络等待后重新校验权限及当前筛选范围。
- 默认聊天保留 16 个完整候选片段、约 24k 字符证据预算，无额外模型证据筛选调用。搜索 API 明确 `rerank=true` 时可选择最多 8 候选、4k 字符、12 秒、零重试的深度筛选。
- 实际执行阶段持久化并流式展示，完成后折叠；输出合批与偏移去重，引用编号映射真实来源。回收站为分类分页主列表，永久删除须最终确认，源文件清理失败保留待清理记录，仅用户再次确认后重试。

## 真实模型观察

原始检索中，复合政策问题的申请表排在第一位；仅改变词面权重与向量融合仍不足以改正，不能据此宣称召回质量已提高。

最终默认检索加入通用文档用途先验后，同两条原问题中学校政策正文的位置分别由第 3、第 4 位变为第 2、第 1 位，前四条不再被申请表占据。本次后端检索耗时约 1.38 秒、0.30 秒，外部模型与缓存会影响时延，不据两个样本计算普遍加速比例。最终浏览器问答检索约 0.73 秒、生成约 10.07 秒，未调用额外重排模型；回答以学校政策第 2、3、7、8 页为依据，明确学院名额资料不足。

两篇本轮创建的合成短文同时进入 parsing/chunking/embedding：约提交后 2 秒均完成向量阶段，随后各自进行摘要和分类。全部 AI 阶段分别约 60 秒、100 秒完成，无失败；这证实并发与早期可检索状态，不代表模型生成延迟已经消失。这一观察发生在本轮最终“短文不扩写”提示调整前，不能作为最终提示调整的加速比例。本轮合成文件及独立测试知识库已按精确 ID 清理，现有用户回收站未清空。

16 候选、11k 字符的模型证据筛选触发 12 秒超时保护，回答仍成功完成；缩小为 8 候选、4k 字符的额外诊断约 9.85 秒成功选择学校政策正文和学院实践办法。因为仍有明显等待，这项能力改为 API 显式选择，默认问答使用无额外网络请求的本地文档用途排序。一次样本不能代表所有主题、所有资料或长期模型时延。
