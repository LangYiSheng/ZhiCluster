# 上传、界面协调与向量批次修复

日期：2026-10-25。依据用户标注的文档列表、标签管理和任务页面，以及目录拖入、批量413和真实Embedding失败问题。

## 原因与修改

| 问题 | 实际原因 | 修改 |
| --- | --- | --- |
| 文档日期缩进、宽屏右侧空白 | 旧版grid的`align-self:center`残留；共享浏览器面板仍沿用窄栏纵排 | 清除残留对齐；按面板容器宽度切换，宽面板显示名称、日期大小、状态三列，窄面板保持左齐纵排 |
| 标签弹窗分散 | 空列表仍保留顶栏新建、空态和底部完成三个区域 | 空态集中展示一个创建入口；有标签时显示工具栏与列表，表单提供颜色实时预览 |
| 任务页两侧留白 | `max-width:1060px`及居中外边距 | 与整理审阅相同的全宽内容区和内边距 |
| 输入框与颜色控件不协调 | 原生颜色矩形与预设圆点混用，输入框状态样式不统一 | 统一输入背景、边框、间距、禁用与聚焦；知识库和标签共用27px彩色圆，保留原生选择及键盘焦点 |
| 拖入目录`Failed to fetch` | 直接提交`DataTransfer.files`里的目录对象，浏览器报`net::ERR_ACCESS_DENIED` | 在drop事件内同步捕获所有入口，再递归读取实际文件；持续读取分页目录结果，并单独传递相对路径 |
| 多文件400/413 | 35个文件超过每批20个；用户实际另一次请求223,771,925字节，超过210MiB入口 | 根据能力接口的数量、文件大小及总量自动拆批；接口未就绪时逐件发送；413进一步拆小，网络错误不自动重放；入口超限返回可读JSON |
| Embedding持续400 | 实际模型入口明确拒绝32条，报告每批最多25条；同资料10条和25条均返回1024维向量 | 只在明确数值批次限制错误时有界收缩并缓存；维持原顺序和维度校验，未知400不猜测重试，不输出提供方原始错误正文 |

模型公开文档与当前实际入口的批次限制可能不同，因此不按模型名硬编码25。参考[阿里云同步Embedding接口文档](https://help.aliyun.com/en/model-studio/text-embedding-synchronous-api)，最终以当前服务的真实错误和成功对照为依据。
