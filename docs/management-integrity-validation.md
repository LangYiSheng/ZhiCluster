# 管理交互与任务历史完整性验收

日期：2026-10-24。使用独立 `zhicluster-eval` 项目和 13000/18000 本机端口，不修改日常知识库、原件或模型配置。

## 修复的真实操作问题

- 文件拖到目录树时，以落点目录上传；重复副本保留原目标，确认中展示文件名和目标路径。网络上传串行接收，阻止迟到请求覆盖另一批待确认文件；资料区隐藏再打开后，旧请求不再重开确认弹窗。
- 换页、排序、类型/状态/未分类筛选清除选择；当前可见文档与选择取交集，刷新后已被其他窗口移走的文档不再参与批量操作。正在确认的文档离开当前新鲜列表时关闭旧确认。
- 末页文档数收缩后回到有效页，等待当前刷新完成后再校正，避免旧空缓存把合法第二页踢回首页。
- 当前目录被删除后，以 API 的 `invalid_folder` 权威错误返回全部文档、第一页并清理旧操作；不把初次加载时的空目录数组误判为删除。
- 拖放目录必须在当前知识库的有效目录列表中，防止另一库的子目录被拖到根落点时，静默改为源库根目录。
- 文件夹树改为一次邻接索引和迭代遍历，去掉 32 层静默截断；保留真实深度缩进、折叠状态和选中标识。移动选项以完整路径区分同名目录，并排除自身整棵子树。6,000 层纯导航回归不依赖递归栈。
- 隐藏资料区暂停文档、任务及统计轮询。

## 200 条之外的任务

原 `/ingestion/jobs` 数组接口保留最近 200 条兼容行为，任务中心改用 `/ingestion/jobs/page`。新接口返回分页、真实总数与完整可见范围的 `all / attention / active / completed` 统计，权限和文档范围一致；`retry_wait` 带错误可同时属于 active 与 attention，类别不能相加当作总数。

资料页用 `document_ids=...&view=current` 为当前可见文档取得状态，最多 200 个去重 ID，每份文档一条；优先运行中的任务，再取排队/等待重试，否则取最新历史。该视图不是“只取创建时间最新任务”。任务详情仍能查看完整历史，统计独立从全库可见范围读取。公开状态投影不加载任务 payload、租约内部字段或文档全文摘要。

隔离 CMRC 库有 848 份文档和 848 条未配置模型的 partial_ready 任务。真实 PostgreSQL 与部署后 HTTP 复核：

| 检查 | 原行为 | 修正后 |
| --- | --- | --- |
| 任务历史可达数 | 最近 200 条 | 17 页找齐 848/848，无重复 |
| 文档按名称第 1 页的任务覆盖 | 8/50 | 50/50 |
| 第 5 页的任务覆盖 | 9/50 | 50/50 |
| 第 17 页的任务覆盖 | 10/48 | 48/48 |
| 待处理总数 | 用返回数组得 200 | 服务端完整统计 848 |

50 条分页响应观测为 23,959 字节，旧 200 条数组为 95,401 字节；不同大小仅作负载说明。完整统计仍需要聚合当前范围的历史，不宣称成本恒定。原始诊断保存在忽略目录 `.data/jobs-diagnostic.json`、`.data/jobs-after.json`。
